# 서버 용량 · 트래픽 검토 (Supabase)

> 2026-11-26 기준. 요금 숫자는 supabase.com/pricing에서 확인한 값. 회원만 서버를 쓴다. (비회원은 기기에만 저장)

## 1. 한 사람이 쓰는 양 (넉넉하게 잡은 값)

| 항목 | 계산 | 한 사람 |
|---|---|---|
| 장부 DB | 기록 1건 ≈ 0.6KB(행 + 색인) × 300건 + 행사 · 종류 · 사진 정보 | **약 0.2MB** |
| 사진 파일 | 장당 0.4MB(1600px로 줄임) + 작은 사진 40KB × 10장 | **약 4.4MB** |
| 전송(egress) · 장부 받기 | 장부 전체 ≈ 100KB × 하루 3번 × 30일 | **약 9MB/월** |
| 전송 · 사진 | 작은 사진은 한 번 받으면 기기에 저장 → 처음 한 번 + 크게 볼 때만 | **약 2 ~ 5MB/월** |

- 앱으로 돌아올 때 장부 받기는 **2분 안에 다시 받지 않게** 막아 두었다. (카톡 보고 돌아오기처럼 잦은 전환에서 전송량 절약)
- 로그인 · 인터넷 재연결 때는 바로 받는다.

## 2. 무료(Free) 요금제로 버틸 수 있는 사람 수

| Free 한도 | 한도 | 버티는 회원 수 (위 계산 기준) |
|---|---|---|
| DB 용량 | 500MB | 약 **2,500명** |
| 파일 저장 (사진) | 1GB | 사진 10장씩이면 약 **230명** ← 가장 먼저 찬다 |
| 전송 (egress) | 5GB/월 | 매달 쓰는 회원 약 **400명** |
| 월간 활성 사용자 (로그인) | 50,000명 | 걱정 없음 |
| 파일 한 개 크기 | 50MB | 사진은 0.4MB라 걱정 없음 |

**결론: 출시 초기(회원 수십 ~ 200명)에는 무료로 충분하다. 사진 저장 공간(1GB)이 가장 먼저 찬다.**

## 3. ⚠️ 진짜 위험: 무료 프로젝트 "일시 정지"

- Supabase Free는 **1주일 동안 요청이 없으면 프로젝트를 멈춘다.** 멈추면 회원 로그인 · 저장 · 사진이 모두 실패한다. (비회원은 영향 없음)
- 회원이 한 명이라도 일주일에 한 번 앱을 켜면 멈추지 않지만, 출시 초기에는 그렇지 않은 주가 생길 수 있다.
- 서버가 "죽는" 경우는 용량보다 이쪽이 훨씬 현실적이다.

### 대책 (둘 중 하나)

| 방법 | 비용 | 장점 | 단점 |
|---|---|---|---|
| **A. Pro 요금제** (추천: 실제 사용자가 생기면) | 월 $25 | 정지 없음, 용량 100배(DB 8GB · 파일 100GB · 전송 250GB), 매일 자동 백업 7일 보관 | 고정 비용 |
| B. 깨우기 요청 (출시 전 · 사용자 적을 때) | 0원 | 무료 유지 | 외부 서비스에 의존. Free 백업 없음 |

**B 설정 방법** (5분): [cron-job.org](https://cron-job.org) 무료 가입 → 새 작업
- 주소: `https://xbffchkgqhiebqtsvyrh.supabase.co/rest/v1/event_types?select=id&limit=1`
- 헤더: `apikey: <앱의 publishable key>` (앱에 이미 들어 있는 공개 키. secret 키는 절대 넣지 않는다)
- 주기: 하루 1번
- 응답은 401(권한 없음)이 정상이다. (로그인 안 한 요청이라 장부는 못 읽음)
- 주의: Supabase는 무엇을 "활동"으로 세는지 정확히 공개하지 않는다. 이 방법은 흔히 쓰이지만 **확실한 보장은 Pro뿐**이다.

## 4. 그 밖에 해 둘 것

- **사용량 알림**: Supabase 대시보드 → Organization → Usage 에서 매달 사용량 확인. Pro로 올리면 **Spend cap(지출 한도)을 켜 둔 채로** 두면 한도를 넘어도 요금이 더 나가지 않는다(대신 넘으면 느려지거나 막힘).
- **백업**: Free는 자동 백업이 없다. 출시 후 실제 장부가 쌓이면 Pro(매일 백업)로 올리는 것을 권한다. 장부는 사용자에게 소중한 기록이라 잃으면 되돌릴 수 없다.
- **사진 용량이 차기 전 신호**: Usage에서 Storage가 800MB를 넘으면 Pro 전환 시점.

## 5. 앱 쪽에서 이미 해 둔 것

| 장치 | 효과 |
|---|---|
| 사진을 1600px · 품질 80으로 줄여서 올림 | 원본 대비 저장 · 전송 약 1/10 |
| 목록은 작은 사진(400px)만 받고 기기에 저장 | 같은 사진을 다시 받지 않음 |
| 행사당 사진 30장 제한 | 한 사람이 공간을 독차지하지 못함 |
| 앱으로 돌아올 때 2분 안 재요청 막기 | 장부 받기 전송량 절약 |
| 주인 없는 사진 파일 정리 (앱 켤 때 1번) | 올리다 끊긴 파일이 공간을 차지하지 않음 |
| 요청 시간 제한 (장부 15초 · 사진 40초) | 느린 요청이 서버 연결을 오래 붙잡지 않음 |
| 엑셀은 휴대폰에서 만듦 | 서버 비용 0 |
