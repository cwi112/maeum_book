# 행사 사진(화환 · 꽃) 기록 기획안

> 상태: **기획 단계** (구현 전). 이 문서로 범위 · 회원/비회원 구분 · 비용을 정한 뒤 구현한다.

## 1. 목표

결혼식 · 장례식 같은 **내 행사**에는 축의금 말고도 화환 · 꽃바구니 · 쌀화환이 많이 온다.
화환 리본에 적힌 이름을 행사가 끝나면 잊어버리기 쉬워서, **행사마다 사진으로 남겨 두고 "누가 보냈는지"를 함께 적는** 기능.

- 기준은 **행사** (받아요 탭 › 행사 상세). 보낸 기록(보내요)에는 넣지 않는다. 내가 화환을 보낸 건 지금처럼 메모에 적는다.
- 나중에 그 사람에게 경조사가 생기면 "화환을 보내 주셨던 분"임을 바로 알 수 있게 한다.

## 3. 회원 · 비회원 (제안)

지금 규칙(비회원 = 기기 DB, 회원 = 서버 DB, 샘플 = 메모리)을 사진에도 똑같이 적용한다.

| 상태 | 사진 저장 위치 | 다른 기기 | 앱을 지우면 | 인터넷 |
| --- | --- | --- | --- | --- |
| 비회원 | **이 기기 앱 폴더** (DB에는 파일 경로만) | ❌ | **사라짐** (처음 추가할 때 한 번 안내) | 필요 없음 |
| 회원 | **서버 (Supabase Storage)** + 이 기기에 작은 사진 캐시 | ✅ | 다시 로그인하면 그대로 | 추가 · 삭제는 필요. 이미 본 사진은 끊겨도 보임 |
| 샘플 둘러보기 | 앱에 들어 있는 예시 사진 2 ~ 3장 (메모리) | — | — | 필요 없음 |

- 비회원 → 첫 로그인 때 "이 기기의 기록을 계정으로 옮길까요?" 팝업에서 **사진도 함께 올린다** (진행률 표시).
- 비회원도 사진 기능을 **막지 않는다.** 대신 사진 칸 아래에 "로그인하면 사진이 안전하게 보관돼요" 안내 → 자연스러운 로그인 유도.
- 사진 원본은 기기 앨범에서 지워도 앱에 남는다. (앱이 자기 폴더/서버에 따로 저장하므로)

## 4. 비용

### 패키지: 0원
| 항목 | 라이선스 |
| --- | --- |
| [`image_picker`](https://pub.dev/packages/image_picker) (Flutter 팀 공식) — 카메라 · 앨범, **크기 줄이기 · 압축 기능 내장** | BSD-3 무료 |
| `path_provider` — 앱 폴더 위치 | BSD-3 무료 |
| 확대 보기 — Flutter 기본 `InteractiveViewer` | 패키지 추가 없음 |
| 서버 업로드 — 이미 쓰는 `supabase_flutter` | 추가 없음 |

### 서버 (회원만): 사진 크기를 줄이면 오래 무료

사진은 올리기 전에 기기에서 줄인다: **긴 변 1600px · JPEG 품질 80 ≈ 장당 0.3 ~ 0.4MB** + 목록용 작은 사진(400px) ≈ 40KB.
(원본 그대로면 장당 3 ~ 5MB → 10배 비쌈)

| Supabase 요금제 (2026-11 확인) | 저장 공간 | 전송(egress) | 장 수로 보면 (장당 0.4MB) |
| --- | --- | --- | --- |
| **Free** 0원 | 1GB | 5GB/월 (+캐시 전송 5GB) | 약 **2,500장** ≈ 회원 250명이 행사 1개에 10장씩 |
| **Pro** $25/월 | 100GB 포함, 넘으면 GB당 $0.0213 | 250GB 포함, 넘으면 GB당 $0.09 | 약 **25만 장**. 1,000장 더 늘 때마다 월 약 $0.01 |

- 이미지 변환(서버에서 작은 사진 만들기)은 Free에 없고 Pro도 유료 → **쓰지 않고 기기에서 작은 사진을 만들어 같이 올린다.**
- 목록에서는 작은 사진만 받고, 한 번 받은 사진은 기기에 저장해 두므로 전송량이 거의 늘지 않는다.
- 남용 방지: **행사당 30장** 제한 (나중에 조정).

> ⚠️ 사진과 별개로 꼭 알아둘 것: **Supabase Free 프로젝트는 1주일 동안 아무 요청이 없으면 일시 정지**된다.
> 정식 출시 후 사용자가 적은 시기에 서버가 멈추면 회원 로그인 · 저장이 안 된다. → 출시 전에 Pro($25/월)로 올리거나, 그 전까지는 주기적으로 깨워 두는 방법을 정해야 한다.

### 개발 시간 (예상)

| 단계 | 내용 | 예상 |
| --- | --- | --- |
| 1 | 비회원: 촬영 · 앨범 · 압축 · 앱 폴더 저장 · 행사 상세 사진 줄 · 전체 화면 보기 · 삭제 | 2일 |

| | **합계** | **5 ~ 6일** |

## 5. 데이터 (구현 메모)

- 새 표 `event_photos`: `id`, `event_id`, `path`(파일 위치), `thumb_path`, `sender_name`, `entry_id`(연결한 받은 기록, 선택), `memo`, `created_at`
  - 기기 DB(drift)에 스키마 버전을 올려 추가, 서버에도 같은 표 + RLS (`user_id` 본인만)
- 서버 파일 위치: 비공개 버킷 `event-photos/{user_id}/{event_id}/{photo_id}.jpg` + `_thumb.jpg`
  - Storage 권한: 폴더 첫 칸이 내 `user_id`일 때만 읽기 · 쓰기 · 지우기
  - 보여 줄 때는 짧게 유효한 서명 링크(signed URL)로 받는다 (공개 링크 없음)
- **삭제 주의**: Supabase 문서상 Storage 파일은 SQL로 지우면 안 되고 **Storage API로 지워야** 한다 (SQL로 지우면 파일이 남음).
  → 행사 삭제 · 계정 탈퇴 때 앱이 먼저 Storage API로 사진을 지운 뒤 DB를 지운다. (지금의 탈퇴 SQL 함수만으로는 사진이 남는다)
- 권한 문구 (앱 심사에서 확인함)
  - iOS: `NSCameraUsageDescription` "화환 · 꽃 사진을 찍어 행사에 남기려고 카메라를 사용해요", `NSPhotoLibraryUsageDescription` "앨범의 사진을 행사에 추가하려고 사진에 접근해요"
  - Android: 카메라 앱 · 사진 선택기를 빌려 쓰는 방식이라 따로 권한을 요청하지 않는다.

## 6. 정해야 할 것 (협의)

| # | 질문 | 제안 |
| --- | --- | --- |
| 1 | 비회원에게도 사진 기능을 줄까 | **준다** (기기에만 저장 + 앱 삭제 시 사라짐 안내 + 로그인 유도) |
| 2 | 사진마다 "보낸 분"을 받을까 | 받는다 (선택 입력). 받은 기록에서 고르면 그 기록에 🌸 표시 |

| 7 | 리본 글자 자동 읽기(OCR)로 보낸 분 자동 입력 | 나중 아이디어 (기기 안 글자 인식은 무료 · 정확도 검증 필요) |
